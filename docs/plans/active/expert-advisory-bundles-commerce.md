# Execution Plan: Expert Advisory, Framework Versions, Bundles, and Commerce

Date: 2026-09-09

## Status

Active

## Outcome

Implement the backend contract in the 2026-09-09 product specification: one
responsible advisor per program, reusable immutable framework versions,
contextual advisory and snapshot-based formal review, manager-owned bundles,
voucher-aware reliable checkout, and learner/parent bundle roadmaps with
certificates. Each milestone is verified and committed before work begins on
the next milestone.

## Context

- Authority: user-provided “OboxSTEAM — Expert Advisory Workspace, Shared
  Frameworks, Bundles and Vouchers” specification (2026-09-09).
- Repository contract: `docs/product/*`, `docs/ARCHITECTURE.md`,
  `docs/WORKFLOW.md`, and `docs/patterns/encoding-invariants.md`.
- Existing review implementation: `ProgramFrameworkService`,
  `CurriculumReviewService`, `ProgramService`, and their unit tests.
- Existing commerce implementation: `PaymentService`, enrollment services,
  invoice/certificate services, Stripe adapter, and their unit tests.
- Navigation uses `rg`/file reads because no CodeGraph MCP tool is available in
  this session.

## Scope

In scope:

- Backend portions of milestones A, B, D, E, and F from the specification.
- Additive API contracts, authorization, notifications, seed data, product
  documentation, EF migrations generated by the pinned CLI, and automated proof.
- Migration compatibility for existing frameworks, reviews, enrollments,
  payments, invoices, and certificates.

Out of scope:

- `OboxSTEAM.FE` and all UI-only requirements because the user explicitly scoped
  implementation to `OboxSTEAM.API`.
- Refunds, subscriptions, stacked vouchers, new retake pricing, binary snapshot
  copies, attachments, reactions, presence, direct messaging, and AI judgments.

## Approach

1. Milestone A: add advisor responsibility and published framework versions,
   migrate/backfill legacy framework data, replace single-program ownership
   validation, expose assignment/version/archive/full-rubric APIs, and prove
   independent advisor authority.
2. Milestone B: add advisory threads/messages/read positions, immutable review
   submissions and curriculum snapshots, private optimistic-concurrency drafts,
   revision summaries, contextual checks, formal decisions, and notifications.
3. Milestone D: add bundle management, publication validation, purchased item
   snapshots, central entitlement/prerequisite resolution, and catalog/read APIs.
4. Milestone E: add pricing quotes, vouchers/reservations, bundle and parent
   checkout, immutable payment/invoice breakdowns, zero-total fulfillment, and
   idempotent activation.
5. Milestone F: add learner/parent roadmaps, later class choice eligibility,
   progress/unlock transitions, one bundle certificate, seed/docs, and complete
   release verification.

Before every milestone commit: generate/check EF migrations where the model
changed, inspect the generated migration and snapshot, run focused tests, run
the full backend test project, and run the API build. Do not begin the next
milestone until the current milestone has a successful commit.

## Risks And Recovery

- Large cross-cutting schema: keep one migration per milestone and inspect every
  generated migration; revert the milestone commit to recover.
- Legacy data ambiguity: deterministic backfill only (framework author or sole
  eligible board expert); leave unresolved advisors null and block only future
  submission.
- Payment races: database constraints plus transactional/idempotent application
  logic; PostgreSQL-specific concurrency proof where repository infrastructure
  permits it.
- Existing API consumers: preserve routes/envelopes and add fields/endpoints
  wherever possible.
- Provider/notification failure: commit domain state first and make fulfillment
  repeatable; pending notifications remain durable.

## Decisions

- 2026-09-09: The pasted specification is accepted product authority for this
  work and supersedes the current one-program framework assumption.
- 2026-09-09: Implement only backend milestones because the explicit repository
  scope is `OboxSTEAM.API`; frontend coordination is recorded only as API
  contract compatibility.
- 2026-09-09: Preserve `Program.FrameworkId` only as a temporary migration/API
  compatibility concern; persisted program assignments pin
  `ProgramFrameworkVersion`.
- 2026-09-09: Startup `MigrationExtensions` no longer backfills framework
  versions or advisors. Seed creates published framework versions via
  `EnsureFrameworkVersionAsync`. Existing production data must already have
  been migrated by Milestone A EF migration / prior backfill before relying on
  this path.
- 2026-09-09: Milestone B adds advisory threads/messages/reads, immutable
  review submissions with curriculum/rubric snapshots, private review drafts
  (409 on stale concurrency), framework-check, revision diffs, and extended
  decision bodies. Startup no longer runs framework/advisor SQL backfill.
- 2026-09-10: ADV seed series added (`SeedService.ExpertAdvisoryDemo.cs`) for
  Milestone B FE fixtures: Maker Advisory Family + `PRG-ADV-*` scenarios A–H
  and advisory inbox rows after robotics `SeedNotificationsAsync`.
- 2026-09-10: Hybrid board follow-up enriches the immutable curriculum snapshot
  with stable program/module/course/activity/material/assignment/milestone
  fields and nesting; adds the submission-scoped board and pin aggregates,
  advisory list filters/previews, field anchors, and structured change
  before/after values. Material metadata remains embedded in the snapshot, so
  a signed preview endpoint is deferred until a provider-backed preview
  requirement is accepted.
